# 技能（Skill）与 MCP 使用指南

> 面向对象：废水监测系统的使用者和维护者
> 配置入口：`http://localhost:5173/agents/config`（智能体配置页）
> 更新日期：2026-08-29

---

## 一、概念速览：技能和 MCP 是什么，有什么区别

| | 技能（Skill） | MCP |
|---|---|---|
| **本质** | 一份"操作手册"（SKILL.md）+ 配套脚本 | 一个外部工具服务进程 |
| **谁来执行** | 智能体读手册 → 用终端跑脚本 | 智能体直接调 MCP 工具函数 |
| **典型用途** | 取监测数据、异常检测、生成报表等**本项目内**的固定流程 | 抓网页、查数据库、读写知识库等**外部**能力 |
| **归属** | 每个智能体有自己的技能目录（作用域隔离） | 只挂给主智能体（全局能力） |
| **类比** | 教科书上的实验规程 | 一台可以遥控的仪器 |

一句话：**技能教智能体"怎么做本项目的事"，MCP 给智能体"新的手"去够外部世界**。

## 二、技能（Skill）

### 2.1 技能的结构

每个技能是一个目录，核心是 `SKILL.md`（智能体读的说明书）：

```
skills/<技能名>/
├── SKILL.md          # 说明书：做什么、什么时候用、怎么调脚本（必需）
└── scripts/
    └── main.py       # 脚本：真正干活的代码（可选，纯指引类技能没有）
```

`SKILL.md` 开头的 frontmatter 决定智能体能否发现这个技能：

```markdown
---
name: data-perception-core
description: 获取监测数据——当任务涉及"获取数据""进水""出水"时使用本技能
---
# （正文写清楚调用方式和参数）
```

**关键机制**：智能体工作时会先用 `skill_view` 浏览自己技能域里的 SKILL.md，按任务匹配 description 选用。**description 写得好不好，直接决定技能会不会被用上。**

### 2.2 技能挂在哪（作用域）

| 归属 | 目录 | 谁能看到 |
|---|---|---|
| 主智能体 | `skills/` | 主智能体（编排、动作指令类技能放这） |
| 数据感知 | `subagents/multi-dimensional-data-perception-agent/skills/` | 只有①数据感知子智能体 |
| 异常检测 | `subagents/anomaly-detection-agent/skills/` | 只有②异常检测子智能体 |
| 规则推理 | `subagents/rule-reasoning-agent/skills/` | 只有③规则推理子智能体 |
| 处置执行 | `subagents/disposition-execution-agent/skills/` | 只有④处置执行子智能体 |

作用域隔离是防"瞎逛"的设计：子智能体只能看到自己的技能，不会满库乱翻。

### 2.3 页面操作（/agents/config → 选中智能体 → 技能 tab）

- **查看/编辑**：点技能卡「查看/编辑」→ 直接编辑 SKILL.md → 「diff 预览」→ 「保存」自动 git 快照（历史可回滚）
- **禁用/启用**：禁用后智能体看不到该技能（如临时下线某个功能）；同一页面会话内可再启用
- **删除**：二次确认 + git 快照，可从 git 历史恢复
- **新建技能**：向导填名称（只能小写字母/数字/连字符）、描述、脚本骨架（空脚本 / 带参数解析模板）
- **技能市场**：一键安装内置模板到当前智能体

### 2.4 内置模板库（6 个）

| 模板 | 建议归属 | 用途 |
|---|---|---|
| regulation-lookup | 主智能体 | 查法规/标准原文（调 Fetch MCP） |
| report-generator | 处置执行 | 生成日报/周报 markdown（jinja2 渲染） |
| plant-onboarding | 主智能体 | 新监测点接入向导（检查 plant-hierarchy.yaml 四段配置） |
| data-export | 数据感知 | 导出监测数据 CSV |
| knowledge-search | 规则推理 | 检索 shared/knowledge 四库 |
| blank-skill | 任意 | 空白骨架，自由发挥 |

### 2.5 写好一个自定义技能（实操示例）

假设要写"查某厂最新一小时流量的技能"：

1. 配置页 → 主智能体（或对应子智能体）→ 技能 tab → 「新建技能」
2. 名称 `flow-check`，描述写**触发场景**（重要）："查询厂区最新流量——当任务涉及'流量''排量'时使用"
3. 骨架选「带参数解析模板」→ 创建
4. 点「查看/编辑」改 SKILL.md 正文，写清三件事：
   - **你做什么**：取指定厂最近 N 小时流量并汇总
   - **怎么调**：给出完整命令行（含 venv python 绝对路径）
   - **输出**：脚本写 `skill_result.json`，把摘要返回给主智能体
5. 改 `scripts/main.py` 实现逻辑（可参考 `shared/skill_templates/data-export` 的写法）
6. 保存 → 去 /chat 问一句会触发它的问题验证

**模板脚本路径提醒**：模板里的 `parents[4]` 是按模板库位置算的项目根相对层级——装到主智能体目录要改成 `parents[3]`，装到子智能体目录改成 `parents[5]`（脚本内有注释说明）。

### 2.6 常见问题

- **技能没被调用**：九成是 description 没写清触发场景。补上"当任务涉及 XX 时使用本技能"这类话。
- **脚本跑失败**：python 必须用 venv 绝对路径 `E:/project/Ecological_env/ecological_env/Scripts/python.exe`（PATH 里的 python 缺依赖）。
- **改了 SKILL.md 不生效**：技能内容在每次智能体会话开始时读取，新对话即生效，无需重启。

## 三、MCP（Model Context Protocol）

### 3.1 MCP 的工作原理

MCP 是给智能体接外部工具的标准协议。每个 MCP server 是一个独立进程（本系统用 npx 启动），启动后向智能体报告自己有哪些工具；智能体对话时按需调用，就像用内置工具一样。

```
配置页安装 → 写入 config.yaml 的 mcp_servers 段
        ↓
重启 agent → agent 主动连接各 server → 工具挂进主智能体工具表
        ↓
对话中提问 → 主智能体看任务匹配 → 自动调 mcp_ 工具 → 拿结果回答
```

**你不需要手动指定用哪个 MCP——智能体根据工具描述自己选。**

### 3.2 页面操作（/agents/config → MCP）

1. **安装预置**：预置卡点「一键安装」→ 写入配置（状态变"已安装"）
2. **测试连接**：起临时握手，显示发现的工具数（`✓ N 工具` 即通）。**首次较慢**——npx 要下载包，属正常
3. **重启生效**：MCP 配置改动后必须重启 agent（页面有「一键重启」按钮）。重启后日志可见 `MCP 工具已挂载: [...]`
4. **停用/删除**：停用=重启后不加载；删除=移除配置

### 3.3 四个预置的用途

| MCP | 智能体能干什么 | 实测工具数 | 边界 |
|---|---|---|---|
| **Fetch** 网页抓取 | 查法规原文、环保标准、任意公开网页 | 2 | 超时 60s |
| **InfluxDB** 时序查询 | 即席查监测数据/元数据（配合 get_data 脚本用） | 9 | 只读 token |
| **Filesystem** 知识库读写 | 读写 `shared/knowledge/` 四库（法规/工艺/违规模式/专家经验） | 17 | **目录锁定 shared/knowledge，碰不了项目其他部分** |
| **Memory** 知识图谱 | 跨会话积累结构化经验（如"某厂某指标的历史教训"） | 20 | 超时 60s |

> 说明：Fetch 用社区包 `@kazuph/mcp-fetch`（官方包已从 npm 下架）；InfluxDB 用社区包 `influxdb-mcp-server`，token 自动从 `.env` 的 `INFLUXDB_TOKEN` 取。

### 3.4 实操：跑通第一个 MCP

以 Fetch 为例的完整链路：

1. MCP 页 → Fetch 卡「一键安装」
2. 「测试连接」→ 等 `✓ 2 工具`
3. 点「一键重启 agent」→ 等 agent 健康检查通过（~30-60s）
4. 打开 /chat 问：**"查一下 GB 18918-2002 中城镇污水处理厂 COD 的 B 级排放限值"**
5. 观察回答——智能体应调用 `mcp_fetch` 抓取网页并在回答中引用来源；若回答里出现网页原文细节，链路即通

### 3.5 接入自定义 MCP

MCP 页「+ 新增接入」：stdio 传输填 command（如 `npx`）+ args（包名），HTTP/SSE 填 url。**必须先测试通过才能保存**（防写进坏配置拖垮 agent）。

安全边界（服务端强制）：
- 目录类参数只允许项目内 `shared/` 子路径，开盘符根/项目根直接拒绝
- 鉴权类 env 值（TOKEN/KEY/SECRET）页面显示脱敏
- 单工具调用超时可配（默认 120s）

### 3.6 常见问题

- **测试连接失败 `WinError 2`**：已修复（自动解析 npx 真实路径）。仍失败先确认 node/npx 可用（`npx --version`）
- **测试连接超时**：首次 npx 下载包慢，重试一次通常就好（包已进本地缓存）
- **装了但对话中不用**：提问要真的需要那个能力（问法规才会触发 Fetch）；也可在主智能体 SKILL.md 里加一句"查法规时优先用 mcp_fetch 工具"强化引导
- **重启后 agent 起不来**：看 agent 控制台日志；MCP 连接失败不会拖垮主智能体（自动降级跳过），删掉有问题的接入再重启即可

## 四、速查表

| 我想… | 去哪 | 动作 |
|---|---|---|
| 让智能体会做一件新的本项目的事 | 技能 tab | 新建 / 市场安装模板 |
| 改某个技能的行为 | 技能 tab | 查看/编辑 SKILL.md → 保存（git 快照） |
| 临时下线某技能 | 技能 tab | 禁用 |
| 给智能体接外部能力（网页/库/文件） | MCP 页 | 一键安装预置 / 新增接入 |
| 验证 MCP 能不能用 | MCP 页 | 测试连接 |
| MCP/供应商配置生效 | 服务管理 | 一键重启 agent |
| 换 LLM 模型 | 供应商页 | 测试通过 → 设默认 → 重启 |

**记住三条铁律**：
1. 技能 description 写触发场景，否则没人用
2. 脚本用 venv python 绝对路径
3. MCP 改配置必重启 agent
