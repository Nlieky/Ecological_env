# 第二批现有功能优化设计

用户已在对话中确认实施。继续使用原项目目录和当前开发分支，保留第一批未提交修改。

## 选择

采用现有架构内的逐项改进，不重构 Agent 并发。共享 Agent 的历史、工具进度队列和窗口上下文仍必须串行隔离。耗时采用实际测量，不承诺未经验证的提速比例。

## 五个独立交付单元

1. AI：流式传输只允许一个终态，断流、网络异常、取消接收都结束前端等待；部分回答保留但显示失败，不被当成完整结论。切换会话后旧请求不可写入新会话。分别展示客户端总耗时、服务端等待/执行和子智能体实测耗时。取消只停止接收，不声称后台任务被取消；不得自动重复提交。
2. 审计：标题与会话标识搜索、分页、URL 会话定位。查询计数与分页条件一致；同时间记录有稳定次序；详情与追溯仍独立加载。搜索或翻页不能让旧响应覆盖新选择。
3. 事件：接入已有筛选分页接口；状态修改经服务器确认后更新显示。保存期间防重复，失败保持原状态。关联图谱的 404 与通信/服务失败分别处理，可重试。关闭详情或切换事件使旧关联请求失效。
4. 配置：保存表示持久化，不代表运行中实例已加载。按真实读取位置给出生效时机；需重启项明确提示，动态读取项标为下一请求/下一读取。供应商与 MCP 保存不声称当前实例已刷新，仍由用户明确确认重启。测试不得修改实际密钥或默认供应商。
5. 图谱与日志：现有 focus 深链接响应路由变化并展示目标；加载失败不说目标不存在。日志可通过实际 session_id 进入现有追溯页。追溯页区分加载失败与成功空记录，并沿用最近一轮/会话级范围说明。旧请求与卸载后响应不能写入当前视图。

## 验收

每单元采用失败测试、最小实现、通过测试、规格审核、质量审核。最终执行完整前后端回归、类型检查、构建及浏览器交互；业务数据、真实事件状态和密钥不作为失败测试的可写样本。对必须重启的服务验证运行代码和实际 HTTP 路径后记录结果。

## 不在范围

登录权限、专家知识审批回滚、新队列/追踪适配器、新事件源、报告导出、Prometheus/Grafana、第三批布局改造、论文分支合并、主分支合并和推送。混合工作区不自动提交，以避免纳入其他任务的修改。
