- 日期：2026-09-14
- 状态：已获用户批准，待执行
- 评估对象：`shared/framework/`（改装版 Hermes Agent 框架）及其在废水虚假排放监测系统中的适配

## 1. 背景与评估前提

### 1.1 已确认的事实基础（探索阶段结论）

| 事实 | 证据 |
|---|---|
| 框架是上游 NousResearch/hermes-agent 的完整内嵌 + 本地改装 | `shared/framework/hermes-agent/`（上游源码，43M，626 个 py）、`hermes_agent/`（包形态副本，`__init__.py` 自述"复制并修改，扩展身份文件读取"） |
| 改装集中在 overlays 层且规模重大 | `hermes-overlays/run_agent.py` 5358 行、`agent/agent_init.py` 1763 行、`tools/orchestrator_tool.py` 193 行 |
| 项目侧接入点唯一且薄 | `backend/services/agent_service.py`（207 行）+ `backend/api/routes/query.py`（1 处引用） |
| 框架链路是当前活链路 | 用户确认 |
| `.hermes/config.yaml` 疑似为空 | 探索时读取无内容 |
| 存在双编排路线 | CLAUDE.md 记载的自研 orchestrator-core（`workspace/skills/orchestrator-core/scripts/`，双层 LLM 驱动，约 12 次调用/流程）vs 本框架 |

### 1.2 用户决策（澄清问题结论）

1. 评估维度：**全面评估**（路线对不对 + 改装质量 + 适配实不实 + 演进方向）
2. 双路线关系：**说不清，由本次评估裁决**
3. 运行现状：**框架链路在跑**
4. 六层架构地位：**初始构想，可在其基础上演进**——评估可建议超越，但须论证；架构与实现的匹配度作为检查项
5. 宗旨：**越详细越好，越具体越好**——所有发现必须落到文件:行号粒度

## 5. 执行方式与边界

- **主审**（逐行）：`hermes-overlays/` 三个文件、`agent_service.py`、接入点与配置
- **并行扫描**（Explore 子代理）：上游框架结构识别与版本比对（粗扫）、四子代理目录盘点、tests 覆盖盘点——与主审不重叠
- **只读原则**：评估全程不修改项目源文件；实证注入代码与运行产物仅放 `/tmp`，跑完即弃
- **执行顺序**：并行探索 → L1 → L2 → L3 → E（穿插）→ L4 → 汇总成文
- **不做什么**：不重构、不修 bug（发现的问题只记录不处理，修复属后续 plan）、不触碰 `~/pi` 与 `~/.openclaw`（参照系仅作机制对照）

## 6. 风险与预案

| 风险 | 预案 |
|---|---|
| overlay 机制比预期复杂（如运行时拼接） | L1.2 升级为运行时验证（打印实际 import 的模块路径） |
| 框架链路起不来（依赖缺失/端口冲突） | 触发 E4 降级；同时本身计入 P0 发现 |
| 上游版本无法识别（无 git 元数据） | 用文件哈希比对 + 关键文件特征推断版本，标注置信度 |
| ctgu-vlm 端点不可用 | 改用 mock LLM 只测调用结构，不测响应质量 |
