# 全系统助手通用页面操作契约

日期：2026-10-16。状态：用户批准后已实施，2026-10-19完成验收；证据与限制见对应实施计划执行记录。

## 目标与边界

将现有页面能力组织成可验证的“理解—准备—确认执行—验证—反馈”闭环。用户的进水pH检测仅为回归案例之一，不加入厂名、指标或自然语言句子的特判。覆盖现有导航、大屏显示/时间/检测、指标筛选、事件筛选/定位、审计定位、图谱定位、日志筛选和配置策略草稿。

保留同一主智能体Skill、8000代理和8642隔离运行实例；保留并行机制及现有蓝白主题。不增加服务、角色、浏览器控制智能体、任意工具调用或自动写入权限。事件写入保持关闭；不扩大配置可写字段。旧专业入口的actionData保持兼容，不以侧栏重构破坏专业页面。

## 已确认的现状

- shared/assistant/protocol.py定义后端schema，前端capabilities.ts重复定义校验，executor.ts另外维护目标页映射。
- 非导航操作统一比较revision，使与业务对象无关的状态变化也导致拒绝。不能简单删除保护。
- 侧栏操作结果追加到会话文本，没有稳定的逐动作执行状态和结果结构。
- dashboard.detect仅携带算法、指标、侧别，实际厂站与时间从执行时的页面读取；必须明确绑定候选时的对象，禁止静默换对象。
- PlantBoardPanel的markPoint仅挂在出水series，action.ts的标注没有完整厂站/窗口/侧别归属。
- 模型协议错误日志只有ValueError类型，不足以区分参数缺失、非法枚举和JSON结构问题。

## 1. 能力定义是事实来源

扩展shared/assistant中的声明式能力定义：id、目标页、中文名称、参数schema、必填字段、允许继承的上下文字段、缺失字段提示、默认策略、就绪要求、失效策略、执行等级。仅存JSON可序列化数据，不接收模型提供的处理器或表达式。

现有/api/assistant/capabilities发布描述；运行时向Skill注入同一份描述。前端执行实现保留本地显式handler白名单，构建时生成受版本控制的静态契约供同步校验，并用一致性测试拒绝漂移。远端描述不能注册可执行代码，版本不兼容时禁止动作并提示刷新。

参数优先级：本轮明确参数 > 当前未完成候选中已明确参数 > 当前页面允许继承值 > 能力声明的默认值。候选变更必须重新校验。用户明确要求当前页面时，以当前快照重建候选，不继承旧页面对象。未知ID、模糊多匹配、未开放操作不猜测。

默认策略由代码声明，不让模型随意生成算法：检测目标明确为恒值/突变/离群时映射对应现有算子；泛称异常且用户委托选择时采用声明的探索性离群检测默认，并解释这只是统计候选，不是超限或违规。若该窗口数据不足，返回不足原因，不静默换算法。仅在业务语义确实不明时追问；缺少侧别且当前同时展示两侧时必须询问，不默认检测出水。

## 2. 准备态与多轮补充

增加结构化待补充意图：capability、已知参数、缺失字段、绑定上下文和契约版本。模型可建议语义映射，但服务端只接受白名单字段并自行计算缺失项、继承项、默认项；来源明确展示为用户指定/页面继承/策略默认。

待补充意图按侧栏会话隔离，由前端随请求提供受限数据，不作为授权来源。历史文本仅辅助理解，不能作为执行回执。切换请求主题时允许取消旧意图；刷新后旧可执行候选不恢复。拒绝自动拼接任意操作序列，首版一次执行一个已注册能力，跨页筛选由目标页处理器自动导航。

候选卡包含动作名称、目标、作用范围、关键参数和默认选择说明。不再仅显示dashboard.detect这样的内部能力名。

## 3. 按能力绑定上下文

绑定信息由前端以发问时的清洗快照生成，不能由模型修改。revision仅用于诊断，不再是所有操作唯一的有效性判断。

| 类别 | 执行前检查 | 执行期间/结果检查 |
|---|---|---|
| 纯导航 | 目标在白名单 | 实际路由到达；导航守卫拒绝如实失败 |
| 显式目标筛选/定位 | 明确目标参数；源页面不用于推断新对象 | 等目标页handler就绪并核实目标/筛选，超时失败 |
| 当前页相对操作 | 路由和该能力声明的对象/条件未变 | 对结果依赖的对象重新检查 |
| 当前窗口检测 | 路由、厂站、来源、采样起止明确且一致；就绪 | 完成时对象/窗口/来源仍一致，否则丢弃旧结果 |
| 配置草稿 | 目标页/允许字段；已有草稿不覆盖 | diff可见，仍由用户应用/保存 |
| 事件变更候选 | 原有服务端proposal/CAS/确认/幂等约束 | 保留未知结果恢复；不降级为普通前端动作 |

加载结束后若厂站/来源/窗口只是从未知变明确，不将旧候选偷偷绑定到新值，应提示“原候选生成时数据未就绪”。页面数据值刷新但绑定对象/窗口未变，可运行对该窗口的当前数据检测，并在回执记录实际数据版本（如现有接口提供）；不承诺不可获得的数据快照隔离。

对象变化提示具体字段，如“采样时段已从A变为B”，提供重新准备入口。导航到目标页等待注册应有明确超时且可取消；不用固定sleep模拟页面就绪。

## 4. 逐动作状态与结果

动作状态：prepared → running → succeeded / empty / failed / stale；awaiting_input作为意图状态而非可点击动作。重复点击running不重复发请求，完成后需重新准备才能再执行。前端取消仅取消结果应用；未真正取消的后端任务不得显示为已停止。

统一回执含success、code、message、target和可选details；检测details包含真实算法、指标、侧别、厂站、时段、异常数量及可见标记数量。handler只在结果已应用/条件已核实后返回成功；HTTP200不是成功证据。零异常用empty（业务成功但无匹配），绘图匹配不到点应明确报结果不可视化，不报已标注。

不再把每次点击回执无限追加到消息正文；卡片显示执行状态与最近一次结构化回执。保存历史可以保留脱敏回执文本，但不可恢复可点击令牌。保留已有事件unknown operation检索键。

## 5. 检测结果呈现修复

标注结果按厂站、来源、时间窗口、指标、侧别归属，窗口或厂站切换后清除/隔离，不污染其他图表。时间戳先按数据来源时区规范成统一时间键，再匹配完整日期；不以slice(5)替代时间一致性。进水/出水分别挂到对应series。

图表显示异常计数及算法/时段摘要；选择“查看结果”定位对应指标卡片。回放时暂停在可见异常位置，且明确提示暂停原因；不自动改变检测绑定的采样窗口。无异常不强行制造红点。标记与原值不一致、时间不匹配、侧别不可见均须反馈。

## 6. 协议与诊断

保留严格JSON/白名单校验，不从无效JSON中猜出可执行动作。增加稳定错误码及字段路径，日志只记录能力名、字段路径、错误码、脱敏任务标识，不记录问题全文、密钥或原始模型正文。用户得到“参数缺失/能力不支持/响应格式错误”等安全说明。

补充状态协议与现有message/actions向后兼容；契约版本不同不能自动执行。没有自动确认、关键词执行捷径或静默旧模型通道。

## 7. 实施顺序与验收门禁

1. 能力声明、版本一致性和按能力上下文校验；先写失败测试，覆盖全部现有能力类别。
2. 待补充意图、参数来源、逐动作状态与真实回执；保留现有写入安全测试。
3. 页面handler逐项迁移，修正检测归属、时间匹配和对应曲线标记。
4. 跨页面真实浏览器与模型验收，先确定性fixture验证执行正确，再真实模型验证表达理解；两者分别记录，不互相替代。

验收矩阵交叉覆盖：导航/筛选/定位/检测/草稿/受限写入；完整参数/省略继承/多轮补充/歧义/不支持；无关刷新/对象切换/来源切换/窗口切换/加载完成/回放；成功/空结果/接口失败/超时/重复点击/刷新恢复。代表性用例至少涵盖事件筛选、日志筛选、审计定位、指标查询、大屏时间切换、进水与出水检测、配置草稿。

真实模型测试同时使用不同厂站、指标和同义表达，不能用截图原话作为唯一成功样例。图表测试检查对应series的实际markPoint和匹配点数，不只看接口与提示文字。真实业务写入全部拦截；事件功能仅测试夹具及关闭开关路径。

完成前运行相关pytest、全量前端Vitest、type-check、build及diff-check；重跑主页面与侧栏并行验证，确认不新增服务。记录准确数量、既有警告及未覆盖范围。保留原目录、当前分支和用户变更，不提交/推送/合并或新建worktree。

## 设计自审

职责分别归属：能力声明负责契约、Skill负责理解、准备器负责补参和绑定、执行器负责调度、页面handler负责操作与核验、卡片负责反馈。没有新服务或无限制代理；未将具体厂名/指标/句式写成规则。默认算法是公开可调整的能力策略，不是对pH的特殊处理。后续详细实施计划必须逐项映射本设计及验收矩阵，不以只通过接口测试代替页面效果。
