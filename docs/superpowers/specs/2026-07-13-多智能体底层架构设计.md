# 多智能体底层架构设计

**日期**: 2026-07-13
**状态**: 设计阶段
**作者**: Claude + 用户讨论

---

## 1. 概述

本文档定义了废水监测系统的底层多智能体架构，基于Hermes Agent框架进行适配，实现主智能体与子智能体的协同工作机制。

### 1.1 核心目标

- 在Hermes Agent框架基础上，实现完整的智能体协同架构
- 支持主智能体通过skill调用子智能体
- 子智能体作为完整的AIAgent实例，具备独立的身份和能力
- 采用同进程架构，实现逻辑隔离

### 1.2 设计原则

- **LLM决策优先**: 让LLM尽可能做决策，通过自然语言描述进行软限制
- **最小化修改**: 尽可能利用Hermes框架原生能力，避免不必要的二次开发
- **架构清晰**: 主智能体、子智能体职责明确，调用路径清晰
- **易于扩展**: 后续可以轻松添加新的子智能体

---

## 2. 架构模式

### 2.1 进程模型

采用**同进程 + 逻辑隔离**架构：

```
┌─────────────────────────────────────────────────────────────┐
│                     单一进程                                  │
│                                                              │
│  ┌──────────────┐        ┌──────────────┐                 │
│  │ 主智能体     │ ────→  │ 子智能体A    │                 │
│  │ AIAgent实例  │        │ AIAgent实例  │                 │
│  └──────────────┘        └──────────────┘                 │
│         │                       │                          │
│         │                       ▼                          │
│         │              ┌──────────────┐                  │
│         └──────────→  │ 子智能体B    │                  │
│                        │ AIAgent实例  │                  │
│                        └──────────────┘                  │
└─────────────────────────────────────────────────────────────┘
```

**同进程的优势**：
- 所有智能体在同一Python进程中运行
- 通过实例隔离实现逻辑隔离
- 避免跨进程通信的复杂性
- 符合主流框架的设计趋势

### 2.2 智能体关系

| 关系类型 | 描述 | 通信方式 |
|---------|------|---------|
| 主智能体 ↔ 子智能体 | 父子关系 | 通过orchestrator-core的call_subagent工具 |
| 子智能体 ↔ 子智能体 | 协作关系 | 通过主智能体中转 |

## 3. 智能体生命周期

### 3.1 创建时机

采用**启动时创建**模式：

```python
# 主智能体启动时
master_agent = AIAgent(identity_path="workspace")

# 同时创建所有子智能体
subagents = {
    "multi-dimensional-data-perception-agent": AIAgent(
        identity_path="subagents/multi-dimensional-data-perception-agent"
    ),
    "anomaly-detection-agent": AIAgent(
        identity_path="subagents/anomaly-detection-agent"
    ),
    "rule-reasoning-agent": AIAgent(
        identity_path="subagents/rule-reasoning-agent"
    ),
    "disposition-execution-agent": AIAgent(
        identity_path="subagents/disposition-execution-agent"
    )
}
```

### 3.2 生命周期管理

- 子智能体与主智能体**生命周期同步**
- 主智能体启动时创建所有子智能体实例
- 主智能体关闭时，所有子智能体实例随之销毁
- 子智能体实例在生命周期内可以被多次调用

## 4. 调用机制

### 4.1 核心原则

**LLM决策 + 软限制**

- LLM拥有完整的决策权，可以动态决定调用哪个子智能体
- 通过SKILL.md中的自然语言描述来引导LLM的决策
- 不使用硬编码规则，而是通过描述进行软限制

### 4.2 调用工具

主智能体的orchestrator-core技能提供`call_subagent`工具：

```python
def call_subagent(
    subagent_name: str,
    task: str,
    context: dict = None
) -> dict:
    """调用子智能体执行任务

    Args:
        subagent_name: 子智能体名称
        task: 需要子智能体执行的任务描述
        context: 可选的上下文信息

    Returns:
        子智能体的执行结果
    """
    subagent = subagents[subagent_name]
    return subagent.run_conversation(task)
```

在`workspace/skills/orchestrator-core/SKILL.md`中通过自然语言描述引导LLM：

```markdown
- **rule-reasoning-agent**: 法规匹配和工艺校验
- **disposition-execution-agent**: 预警生成和处置协调
```

## 6. Hermes框架适配

### 6.1 适配策略

- 尽可能利用Hermes框架原生能力
- 需要修改的地方重点实现
- 避免过度定制化

### 6.2 需要修改的部分

#### 6.2.1 支持自定义identity_path

**问题**: Hermes默认从HERMES_HOME读取身份文件

**解决方案**: 为AIAgent添加`identity_path`参数

```python
# 原生：从HERMES_HOME读取
agent = AIAgent(load_soul_identity=True)

# 适配后：从自定义目录读取
agent = AIAgent(
    identity_path="workspace",  # 相对于项目根目录
    load_soul_identity=True
)
```

#### 6.2.2 身份文件支持

Hermes框架已支持7个身份文件：
- IDENTITY.md - 身份卡片
- SOUL.md - 身份和个性
- AGENTS.md - 工作区规范
- MEMORY.md - 长期记忆
- USER.md - 用户信息
- TOOLS.md - 工具配置
- HEARTBEAT.md - 周期性任务

无需修改，直接使用。

### 6.3 路径设计

**原则**: 使用相对路径，相对于项目根目录

```python
# 项目根目录: E:\project\Ecological_env

master_agent = AIAgent(
    identity_path="workspace"  # 解析为 E:\project\Ecological_env\workspace
)

subagent = AIAgent(
    identity_path="subagents/anomaly-detection-agent"
    # 解析为 E:\project\Ecological_env\subagents\anomaly-detection-agent
)
```

## 8. 核心实现

### 8.1 子智能体实例管理

在主智能体启动时创建所有子智能体实例：

```python
class SubagentManager:
    def __init__(self):
        self.subagents = {}

    def create_subagents(self):
        """创建所有子智能体实例"""
        subagent_configs = {
            "multi-dimensional-data-perception-agent": "subagents/multi-dimensional-data-perception-agent",
            "anomaly-detection-agent": "subagents/anomaly-detection-agent",
            "rule-reasoning-agent": "subagents/rule-reasoning-agent",
            "disposition-execution-agent": "subagents/disposition-execution-agent"
        }

        for name, path in subagent_configs.items():
            self.subagents[name] = AIAgent(
                identity_path=path,
                load_soul_identity=True
            )

    def get_subagent(self, name: str) -> AIAgent:
        """获取子智能体实例"""
        return self.subagents.get(name)
```

### 8.2 call_subagent工具实现

```python
# workspace/skills/orchestrator-core/scripts/subagent_tools.py

def call_subagent(
    subagent_name: str,
    task: str,
    context: dict = None
) -> dict:
    """调用子智能体执行任务

    Args:
        subagent_name: 子智能体名称
        task: 需要子智能体执行的任务描述
        context: 可选的上下文信息

    Returns:
        子智能体的执行结果，包含:
        - success: bool - 是否成功
        - result: str - 执行结果
        - error: str - 错误信息（如果有）
    """
    try:
        subagent = subagent_manager.get_subagent(subagent_name)
        if not subagent:
            return {
                "success": False,
                "error": f"子智能体 {subagent_name} 不存在"
            }

        result = subagent.run_conversation(task)
        return {
            "success": True,
            "result": result
        }
    except Exception as e:
        return {
            "success": False,
            "error": str(e)
        }
```

### 8.3 orchestrator-core的SKILL.md

```markdown
# 编排器核心技能

## 技能描述

本技能负责主智能体的核心编排功能，包括：
- 子智能体调用管理
- 任务分发和结果聚合
- 子智能体协作协调

## 子智能体职责

### multi-dimensional-data-perception-agent（多维数据感知子智能体）
- 负责多源数据获取
- 数据质量检查和清洗
- 时序数据对齐
- 字段标准化处理

### anomaly-detection-agent（异常检测子智能体）
- 5类异常识别：平稳、突变、趋势、周期、高频波动
- 4类违规检测：插瓶干扰、人工拟合、稀释排放、恶意逃避
- 置信度评估

### rule-reasoning-agent（规则推理子智能体）
- 法规规则匹配
- 工艺机理校验
- 专家推理

### disposition-execution-agent（研判预警与处置执行子智能体）
- 融合共识算法
- 三级预警分类
- 工单生成

## 调用原则

1. **单一职责优先**: 优先调用最相关的子智能体，而非同时调用多个
2. **协作按需**: 当任务需要多领域协作时，可以按顺序调用多个子智能体
3. **结果传递**: 前一个子智能体的结果可以作为后一个子智能体的输入
4. **避免重复**: 不要为同一任务重复调用同一个子智能体

## 典型场景

### 数据异常检测流程
1. 调用 multi-dimensional-data-perception-agent 获取数据
2. 调用 anomaly-detection-agent 检测异常
3. 调用 rule-reasoning-agent 进行规则验证
4. 调用 disposition-execution-agent 生成预警

## 工具说明

### call_subagent
调用指定的子智能体执行任务。

参数:
- subagent_name: 子智能体名称
- task: 任务描述
- context: 可选上下文

返回:
- success: 是否成功
- result: 执行结果
- error: 错误信息
```

## 9. 技术决策记录

### 9.1 为什么选择同进程而非跨进程？

**决策**: 采用同进程架构

**理由**:
1. 主流框架（Hermes、OpenClaw、LangGraph、CrewAI）都采用同进程架构
2. 跨进程隔离对当前项目需求没有实质性帮助
3. 同进程实现更简单，性能更好
4. 逻辑隔离已经足够满足需求

### 9.2 为什么采用启动时创建而非按需创建？

**决策**: 启动时创建所有子智能体实例

**理由**:
1. 简化实现，不需要动态创建机制
2. 子智能体实例可以保持状态，支持多次调用
3. 启动时创建可以提前发现问题

### 9.3 为什么采用主智能体中转而非子智能体直接通信？

**决策**: 子智能体通过主智能体中转通信

**理由**:
1. 符合orchestrator-core的设计定位
2. 更容易实现和管理
3. 主智能体可以控制通信流程
4. 符合主流框架的设计模式

### 9.4 为什么主智能体看不到子智能体的skill？

**决策**: 每个智能体的skill互相独立

**理由**:
1. 符合智能体隔离的原则
2. 简化系统复杂度
3. 每个智能体专注于自己的职责
