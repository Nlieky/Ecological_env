# 废水监测系统架构重构设计文档

**日期**: 2026-05-29
**版本**: 1.0
**状态**: 待审批

---

## 1. 概述

### 1.1 设计背景

当前废水监测系统基于专利架构实现了4个子智能体，但在实际运行中发现以下问题：

1. **子智能体依赖问题**：data-governance-agent 和 feature-analysis-agent 存在强耦合，后者无法独立工作
2. **职责边界不清**：特征分析与异常检测的边界模糊，存在功能重叠
3. **缺少闭环执行**：识别出违规后缺少预警分级和处置执行机制
4. **数据维度单一**：仅处理水质数据，未纳入流量、工况等多维数据

### 1.2 重构目标

1. **优化子智能体结构**：合并数据治理相关智能体，明确职责边界
2. **增加多维数据支持**：纳入水质+流量+工况(8类)等多维时序数据
3. **完善闭环执行**：新增研判预警与处置执行智能体，实现业务闭环
4. **强化LLM驱动**：确保全流程由LLM动态决策，脚本只负责具体计算

## 3. 主智能体设计

### 3.1 动态编排机制

主智能体根据任务类型智能选择子智能体组合：

```
输入: 任务类型 + 数据状态 + 历史结果
         │
         ▼
┌─────────────────┐
│ 违规检测任务     │ → 全部4个子智能体
└─────────────────┘
         │
         ▼
┌─────────────────┐
│ 分析查询任务     │ → 数据感知+异常检测
└─────────────────┘
         │
         ▼
┌─────────────────┐
│ 历史回溯任务     │ → 跳过异常检测
└─────────────────┘
         │
         ▼
并行执行策略: 数据感知 ‖ 异常检测 → 规则推理 → 预警执行
```

### 3.2 LLM驱动流程

```
1. 语义解析阶段
   ├─ 读取: IDENTITY.md, AGENTS.md, MEMORY.md
   ├─ 输入: 自然语言指令 / 数据触发信号
   └─ 输出: IntentResult (意图类型+置信度+实体)

2. 任务编排阶段
   ├─ 读取: SOUL.md, HEARTBEAT.md
   ├─ 决策: 哪些子智能体需要参与
   ├─ 决策: 执行顺序 (串行/并行)
   └─ 输出: StructuredTask + ExecutionPlan

3. 子智能体协调阶段
   ├─ 读取: 各子智能体身份文件
   ├─ 决策: 每个子智能体的脚本选择
   ├─ 决策: 每个子智能体的参数配置
   ├─ 处理: 子智能体输出结果
   └─ 决策: 结果传递给下一个智能体

4. 结果整合阶段
   ├─ 读取: 知识库
   ├─ 综合: 各子智能体的输出
   └─ 输出: 自然语言报告
```

## 4. 子智能体设计

### 4.1 多维数据感知智能体 (重构)

**目录名称**: `multi-dimensional-data-perception-agent`

**身份信息**:
- Name: 多维数据感知子智能体
- Creature: Multi-Dimensional Data Processor
- Vibe: 严谨、可靠、多源整合
- Emoji: 📊

**核心能力**:
1. 多维时序数据获取 (水质+流量+工况8类)
2. 数据分解与对齐
3. 数据清洗与质控
4. 标准化归一化

**支持的数据类型**:
- 水质数据: pH、COD、TN、TP、氨氮、悬浮物等
- 流量数据: 进水流量、出水流量、排放量等
- 工况数据(8类):
  - 设备状态: 进水泵、鼓风机、污泥泵等
  - 工艺参数: 溶解氧、污泥浓度、回流比等
  - 维护记录: 反冲洗、检修、停运计划等
  - 生产记录: 生产批次、产量变化等
  - 污染源信息: 名称、行政区划、联系人等
  - 监测点信息: 名称、编号、类型、级别等
  - 设备信息: 类别、名称、启用日期、状态等

**LLM决策范围**:
- 选择数据源策略 (CSV/API/数据库)
- 决策时间对齐方式
- 决策数据质控阈值
- 分析数据质量报告

**脚本结构**:
```
subagents/multi-dimensional-data-perception-agent/
├── IDENTITY.md
├── AGENTS.md
├── SOUL.md
├── MEMORY.md
├── TOOLS.md

├── skills/
│   └── data-perception-core/
│       ├── SKILL.md
│       └── scripts/
│           ├── data_acquisition.py      # 多源数据获取
│           ├── data_decomposition.py    # 多维数据分解
│           ├── time_alignment.py         # 时序对齐
│           ├── data_cleaning.py          # 数据清洗质控
│           └── standardization.py        # 标准化归一化
└── memory/
```

**输出格式**:
```json
{
  "status": "success",
  "data": {
    "water_quality": {},
    "flow": {},
    "equipment": {},
    "process": {},
    "maintenance": {},
    "production": {},
    "source_info": {},
    "monitoring_point": {}
  },
  "quality_score": 0.95,
  "timeliness": "aligned"
}
```

### 4.2 异常检测子智能体 (保持)

**目录名称**: `anomaly-detection-agent`

**身份信息**:
- Name: 异常检测子智能体
- Creature: Anomaly Detector
- Vibe: 警惕、全面、谦逊
- Emoji: 🔍

**核心职责**:
- 数据驱动异常识别
- 5类异常特征检测
- 置信度评估

**不负责**: 违规判定（由规则推理子智能体负责）

**支持的异常类型**:
1. 平稳异常: 恒定值检测
2. 突变异常: 突变点检测
3. 趋势异常: 趋势违背检测
4. 周期异常: FFT周期检测
5. 高频波动: 高频噪声检测

**LLM决策范围**:
- 选择检测算子组合 (统计/ML/DL/专用)
- 配置算子参数 (阈值/窗口/灵敏度)
- 分析检测结果，生成结构化报告

**输出格式**:
```json
{
  "anomalies": [
    {
      "type": "平稳异常",
      "indicator": "COD",
      "time_range": ["2024-05-29T02:00", "2024-05-29T04:00"],
      "confidence": 0.95,
      "evidence": {
        "std_dev": 0.05,
        "duration": "2h",
        "values": [45.2, 45.1, 45.3]
      }
    }
  ]
}
```

### 4.3 规则推理子智能体 (重构)

**目录名称**: `rule-reasoning-agent`

**身份信息**:
- Name: 规则推理子智能体
- Creature: Knowledge Reasoner
- Vibe: 博学、精准、公正
- Emoji: ⚖️

**核心框架**: 规则匹配 — 机理推演 — 逻辑判定

**核心职责**:
- 接收异常检测子智能体的异常特征
- 规则匹配: 从知识库检索相关规则
- 机理推演: 结合工况/工艺/法规进行推演
- 逻辑判定: 判定违规类型，过滤误报

**支持的违规类型**:
1. 插瓶干扰: 恒定值 + 工况正常
2. 人工拟合: 过度平滑 + 分布异常
3. 稀释排放: 多指标同步下降 + 去除率异常
4. 恶意逃避: 数据缺失 + 非工作时间空白

**规则引擎设计**:
- 规则配置: YAML/JSON格式，支持热更新
- 规则类型: 法规规则/工艺规则/专家经验规则
- 推理机制: 前向链/后向链/混合推理

**LLM决策范围**:
- 从知识库检索相关规则
- 规则匹配与优先级排序
- 机理推演 (如: 脱硫塔反冲洗正常工况)
- 逻辑判定 (否决/降级/升格)

**脚本结构**:
```
subagents/rule-reasoning-agent/
├── skills/
│   └── rule-reasoning-core/
│       └── scripts/
│           ├── rule_matcher.py           # 规则匹配引擎

│           ├── expert_reasoner.py        # 专家经验推理
│           ├── violation_detector.py     # 违规判定器(新增)
│           └── false_positive_filter.py  # 误报过滤器
```

## 7. LLM驱动原则

### 7.1 全LLM驱动定义

本系统采用"LLM决策+脚本执行"模式：

- **LLM负责**: 脚本选择、参数配置、结果分析
- **脚本负责**: 具体计算（数据读取、算法执行、格式转换）
- **特别注意**: LLM不需要直接做异常检测判断，只需动态调用参数给模型

### 7.2 各智能体LLM使用

| 智能体 | LLM决策内容 | 脚本执行内容 |
|--------|-------------|-------------|
| 主智能体 | 任务解析、子智能体选择、参数配置 | 无（纯协调） |
| 多维数据感知 | 数据源选择、质控策略、对齐方式 | 数据读取、清洗、对齐 |
| 异常检测 | 算子选择、参数配置、结果分析 | 异常检测计算 |
| 规则推理 | 规则检索、推演逻辑、判定决策 | 规则匹配、验证计算 |
| 预警执行 | 融合策略、分级判定、工单生成 | 工单格式化、推送执行 |

## 9. 总结

本设计将原有的4个子智能体重构为新的架构：

| 智能体 | 类型 | 状态 | 核心职责 |
|--------|------|------|----------|
| 主智能体 | 交互与调度中枢 | 增强编排能力 | 语义解析、意图锚定、任务编排、动态调度 |
| 多维数据感知智能体 | 数据处理 | 重构 | 8类多维数据获取、分解、清洗、标准化 |
| 异常检测子智能体 | 数据驱动检测 | 保持 | 5类异常特征检测、置信度评估 |
| 规则推理子智能体 | 经验驱动推理 | 重构 | 规则匹配、机理推演、违规判定、误报过滤 |
