# AI 助手、智能体审计与日志中心优化设计

## 目标

本轮只优化三个既有功能，不新增认证授权、知识审批、业务数据接入等下一阶段能力：

1. AI 助手允许多个会话保留各自的执行与展示状态；切换会话不再中止其他会话的流式接收。
2. 智能体审计提供符合系统主题的搜索体验，并稳定支持标题片段、会话 ID 与多关键词搜索。
3. 日志中心从“逐类原始表格”改造成“异常优先、可筛选、可展开追溯”的运维工作台。

## 已确认根因

### AI 助手

当前 `chat` store 只有一组全局 `messages/loading/sessionId/AbortController`。`openConversation()` 与 `startNewConversation()` 都会调用 `invalidate()`，从而终止正在进行的 SSE 接收。后端任务可能仍然运行，但前端失去该任务的增量内容和完成事件，因此两个会话无法独立显示。

### 智能体审计

后端现有 `contains` 查询已经支持中文标题片段；实测“金桥”“7月14”“历史上”均能命中。主要缺陷是前端仅在表单提交时查询，输入过程没有防抖搜索、执行反馈、匹配统计或关键词规范化，且搜索框为浏览器原生样式，造成“必须输入完整标题”的使用感受。

### 日志中心

当前页面按单一 `log_type` 拉取并以表格平铺，无法同时观察错误、警告与慢调用，也没有内容搜索、时间范围、模块组合筛选和清晰的上下文层级。详情字段直接遍历，信息密度高但可读性低。

## 方案

### 1. AI 助手：会话级运行时状态

- 将单一全局流改成以 `conversationId` 为键的运行时状态表。
- 每个会话独立保存消息、状态、错误、SSE 控制器、阶段耗时与最后活动时间。
- 状态统一为 `idle / queued / running / completed / failed / cancelled`。
- 切换会话只改变当前视图，不取消其他会话的 SSE；只有显式停止、删除会话或清空历史才终止对应流。
- 左侧会话目录显示：
  - `running`：旋转圆圈和“回答中”；
  - `queued`：虚线圆圈和“排队中”；
  - `failed`：错误标记；
  - `completed`：完成圆点短暂保留后回归普通状态。
- 输入框只根据“当前会话”是否执行来禁用。用户可切到另一个空闲会话继续提问。
- 后端主 Agent 目前仍是串行执行，因此第二个请求可能处于排队而不是并行推理；页面必须如实区分“排队中”和“回答中”。
- 浮动动作助手继续使用独立动作通道，不与主聊天会话状态混用。

### 2. 智能体审计：可理解的模糊搜索

- 搜索框替换为系统统一的图标输入框，提供清除按钮、加载状态、命中数量和空结果引导。
- 输入后 300ms 防抖搜索，同时保留 Enter 与搜索按钮。
- 前后端统一执行 `trim`、连续空白折叠；多个关键词按“全部关键词均命中标题或会话 ID”处理。
- 切换关键词时页码重置为 1；迟到请求不得覆盖新结果。
- 搜索结果保留当前正在查看的审计详情，并明确提示其是否已不在筛选结果中。
- 不做全文消息内容检索，避免本轮引入高成本数据库迁移；输入提示会明确搜索范围。

### 3. 日志中心：异常优先的日志流

- 顶部提供全部、错误、警告、慢调用四个摘要筛选入口。
- 工具栏提供关键词、模块、时间范围筛选；筛选条件统一传给后端，避免只过滤当前页。
- 主体使用扫描友好的日志流：时间、级别、摘要、模块、耗时为第一层；结构化详情按需展开。
- 错误、警告和慢调用用文字、图标和颜色共同表达，不只依赖颜色。
- 存在 `session_id` 时保留“查看追溯”入口。
- 后端增加统一日志查询聚合层，把现有六类日志映射为统一条目；旧的按类型接口参数继续兼容。
- 日志级别采用保守推导：错误表为 error；失败/超时语义为 error；超过阈值为 warning/slow；其余为 info。推导规则集中在后端并有测试覆盖。

## 数据与错误处理

- 会话 SSE 完成后刷新历史元数据，但不得覆盖本地仍在运行的会话状态。
- 页面刷新后，无法恢复已断开的浏览器 SSE；此时从服务端历史恢复已落库消息，并将未确认任务标为“状态待确认”，不伪装成仍在流式接收。
- 审计与日志查询均采用请求代次门，忽略迟到响应。
- 日志聚合中单一日志源失败时返回明确错误，不把不完整结果展示为“全部正常”。

## 测试与验收

### 自动化

- Store 单元测试：两个会话同时存在运行状态、切换不 abort、各自增量互不串流、删除只取消目标会话。
- 组件测试：会话状态圆圈、当前会话输入限制、排队/失败展示。
- 审计测试：标题片段、多关键词、空白规范化、防抖、迟到响应、空结果。
- 日志测试：组合筛选、级别推导、慢调用、详情展开、会话追溯链接、分页和错误态。
- 执行 TypeScript 检查、Vitest 相关测试、前端构建和后端针对性 Pytest。

### 人工验收

1. 会话 A 提问后切到会话 B；A 左侧持续旋转，B 可继续提交，返回 A 可见其持续更新或完成结果。
2. 审计输入“金桥”“7月14”“历史 违规”等片段均得到合理结果，清除后恢复完整列表。
3. 日志中心可一键只看错误或慢调用，展开上下文，并进入对应会话追溯。

## 非本轮范围

- 不提升主 Agent 的实际并行推理能力；只让多会话请求可靠驻留并显示真实排队/执行状态。
- 不建设日志实时推送、长期归档、告警规则和通知渠道。
- 不引入 Prometheus 或 Grafana。
- 不处理认证授权和知识变更审批。
