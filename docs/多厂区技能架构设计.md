# 多厂区技能(Skill)架构设计

> 状态:设计稿(2026-07-27)
> 目标:为未来接入多厂区,确立「智能体通用 + 厂区 skill 定制」的架构路线

---

## 1. 背景与目标

未来要接入**多个污水处理厂区**。每个厂区的监测指标、工艺逻辑、阈值、数据源可能不同。要求:

- **智能体通用**:主智能体 + 4 个子智能体,所有厂区共用一套,代码不动
- **厂区差异通过 skill 定制**:指标/逻辑/阈值差异写进 skill,不改智能体代码
- **加新厂区 = 加一套厂区 skill**:智能体零改动

核心理念一句话:**智能体是通用骨架,skill 是厂区适配层**。

---

## 2. 核心理念

```
智能体通用(主+子,所有厂区共用)
       +
skill 作用域(每个 skill 属于一个智能体,HERMES_HOME 限定)
       +
厂区 skill 定制(厂区差异写进 skill 内容)
```

关键洞察(2026-07-27 实验验证):**skill 必须在智能体下(作用域),而不是全局**。当年 LLM 瞎逛就是因为 skill 全局(没作用域),LLM 满库乱翻;把作用域写清楚(`HERMES_HOME=子智能体`),瞎逛消失,且不挑模型。

## 4. 架构设计

### 4.1 三层结构

```
主智能体(workspace/,通用)
  ├─ 编排 skill(orchestrator-core/SKILL.md):决定调哪些子智能体 + 厂区路由
  └─ call_subagent(subagent, task, 厂区) → 子智能体
       │
       └─ 子智能体(subagents/X/,通用)
            ├─ 通用 skill(数据感知/异常/规则/处置 的通用流程)
            └─ 厂区 skill(skills/厂区A/, skills/厂区B/):厂区定制
```

### 4.2 厂区 skill 组织(每个子智能体下)

```
subagents/multi-dimensional-data-perception-agent/skills/
  ├─ data-perception-core/SKILL.md   # 通用:指标定义、取数流程、脚本入口
  ├─ 厂区金桥/SKILL.md                # 金桥厂定制:特定指标/阈值/数据源 tag
  └─ 厂区XX/SKILL.md                  # 新厂区定制
```

LLM 的 `skill_view` 在作用域内看到「通用 + 各厂区」skill,按 task 里带的厂区标识选用对应的。

### 4.3 厂区路由

主智能体编排 skill(`orchestrator-core/SKILL.md`)含厂区路由逻辑:
- 用户提问或数据信号带厂区标识 → 主智能体识别厂区
- `call_subagent(subagent, task, 厂区)` 把厂区传给子智能体
- 子智能体 task 含厂区 → `skill_view` 选该厂区 skill 执行

### 4.4 数据隔离

- InfluxDB `measurement=wastewater`,tag `plant_id`(导入时已写,见 `import_to_influxdb.py`)
- `get_data` 加 `plant_id` 参数,Flux 查询按 plant_id 过滤(当前单厂区不传 = 全量;多厂区传具体 plant_id)
- 每个厂区的监测数据在 InfluxDB 里靠 plant_id tag 天然隔离

---

## 5. 关键机制

| 机制 | 作用 |
|---|---|
| **HERMES_HOME 作用域** | 子智能体 `skill_view` 只翻自己的 `skills/`,边界清晰防瞎逛 |
| **skill_view 动态读取** | LLM 按需读 SKILL.md(不预加载),支持新增 skill/厂区,智能体不动 |
| **厂区 skill 定制** | `skills/厂区/` 下 SKILL.md 定制该厂区指标/逻辑/阈值 |
| **数据 plant_id tag** | 多厂区数据在 InfluxDB 天然隔离,get_data 按 tag 过滤 |
| **主智能体厂区路由** | 编排 skill 决定调哪个厂区的子智能体流程 |

---

## 6. 实现路径(从单厂区到多厂区)

### 阶段 1:主智能体改用 skill_view(统一机制)

- `start_agent.py` 去掉预加载 `orchestrator-core/SKILL.md`
- 主智能体 `enabled_toolsets` 含 `skills` + prompt 引导 `skill_view` 读编排 skill
- `HERMES_HOME=workspace` → `skill_view` 翻 `workspace/skills/`(orchestrator-core 编排 skill)
- 验证:主智能体用 skill_view 读编排 skill → 调 call_subagent
- 收益:主智能体也支持动态 skill(未来编排 skill 可扩展,不预加载)

### 阶段 2:厂区 skill 结构

- 子智能体 `skills/` 下加厂区 skill 子目录(如 `skills/厂区金桥/SKILL.md`)
- SKILL.md 设计规范:通用流程引用 + 厂区特定参数(指标列表/阈值/数据源 tag/脚本参数)
- LLM skill_view 看到「通用 + 厂区」,按 task 厂区选

### 阶段 3:多厂区数据

- InfluxDB 导入时确保 plant_id tag 正确(`import_to_influxdb.py` 已写 plant_id)
- `get_data.py` 加 `--plant` 参数,Flux 查询按 plant_id 过滤
- `run_anomaly_detection_simple.py` 等同样按 plant 过滤

### 阶段 4:主智能体厂区路由

- `orchestrator-core/SKILL.md` 加厂区路由:识别用户/数据厂区 → call_subagent 传厂区
- 子智能体 task 模板带厂区字段
- 多厂区并发查询的 session 隔离(已有 sessions/<session>/)

## 8. 设计原则回顾

- ✅ **智能体通用,skill 定制**:加厂区不动智能体代码
- ✅ **skill 在智能体下(作用域)**:HERMES_HOME 限定,防瞎逛
- ✅ **hermes 原生 skill_view**:不预加载,动态发现,支持扩展
- ✅ **数据 tag 隔离**:plant_id 天然隔离多厂区数据
- ⚠️ **不挑模型**:作用域是关键(已验证 ctgu-vlm 也不瞎逛)
